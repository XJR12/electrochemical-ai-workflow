# 工具发现与评估

先找成熟工具，再决定自己写；避免重复造轮子。

## 流程

1. 需求模板：任务、输入格式、输出、约束（AI 代填，人确认）
2. 检索：本地已有工具 → Codex skill/插件 → GitHub/PyPI/HuggingFace → 期刊软件（JOSS/SoftwareX 等）→ 领域精选清单
3. 评估矩阵：功能匹配、数据格式支持、成熟度、科研可信度、可追溯性、依赖成本、许可证
4. 决策：直接使用 / 封装后使用 / 自己写（附理由）
5. 存档：评估记录写入本目录，避免以后重复搜索

## 决策规则

- 预期自研工作量很小（约半天内）→ 直接自己写，不值得搜
- 有成熟工具且格式兼容 → 直接使用
- 有工具但需适配 → 封装后使用
- 搜索超时或没有可信候选 → 用最优候选，或停下来由人决定
