# 科研 AI 助手工作流构想（简明版）

## 核心目标

不是让 AI 替代科研人员，而是：

> **把重复、机械、耗时间的工作交给 AI，把实验设计、结果判断、科学思考留给自己。**

AI = 助手/调度员
代码 = 工具
数据 = 核心资产
人 = 最终判断者

---

# 1. 文献搜索与知识管理

目标：

> 从“找论文”升级为“建立个人知识库”。

工作流：

```
研究问题
↓
AI检索相关论文
↓
提取：
- 材料体系
- 合成条件
- 表征方法
- 性能参数
- 机理解释
↓
形成结构化数据库
```

例如：

“整理酸性OER Ru基催化剂”

输出：

| 材料 | 制备方法 | 性能 | 稳定性 | 机理 |
| -- | ---- | -- | --- | -- |

注意：

AI负责整理和总结，不替代人工判断论文可信度。

---

# 2. 数据处理自动化（最容易落地）

目标：

> 减少Origin、Excel等重复操作。

例如电化学：

输入：

```
LSV.txt
CV.txt
EIS.txt
```

输出：

```
LSV图
Tafel图
EIS拟合结果
参数汇总表
```

原则：

* 原始数据不修改
* 分析过程可追溯
* 计算公式明确

推荐模式：

```
Raw Data
↓
固定分析脚本
↓
Result
↓
Figure
```

AI负责：

* 写代码
* 修改代码
* 维护流程

程序负责：

* 数学计算
* 数据处理

---

# 3. 图片/视觉分析

目标：

> 利用AI辅助分析未知形貌和表征图片。

适合：

* SEM粒径统计
* 形貌分类
* 图片增强
* 不同样品对比

例如：

SEM图片：

AI辅助判断：

* 颗粒大小
* 团聚情况
* 形貌相似论文

但注意：

图片不能单独确定材料。

例如：

SEM看到纳米颗粒 ≠ 一定是RuO₂。

必须结合：

* XRD
* XPS
* EDS
* Raman

AI只能辅助，不作为最终物相判断。

---

# 4. 工具发现与评估（非常重要）

原则：

> 不要为了学习代码而写代码。

先判断：

“有没有成熟工具？”

流程：

```
需求
↓
搜索已有软件/开源工具
↓
评估：
- 是否稳定
- 是否适合科研
- 是否可追溯
- 是否支持自己的数据格式
- 是否被论文使用
↓
选择：
直接使用 / 修改 / 自己开发
```

科研人员应该：

优先使用成熟工具。

自己开发只是最后选择。

---

# 5. 未来科研 Agent 模式

理想结构：

```
                 AI Agent
                    |
    --------------------------------
    |              |               |
文献工具       数据工具        图片工具
    |              |               |
论文库        Python脚本       图像分析
```

AI负责：

* 理解任务
* 调用工具
* 管理流程

工具负责：

* 具体计算
* 数据处理

---

# 6. 安全原则（科研必须）

不要：

```
实验数据
↓
AI
↓
论文结果
```

应该：

```
原始数据（只读）
↓
分析程序
↓
处理结果
↓
人工确认
↓
论文
```

规则：

1. AI不能修改原始实验数据
2. AI不能生成不存在的实验结果
3. 所有结果必须能追溯来源
4. 保留分析脚本和计算过程

---

# 7. 对个人科研 AI 助手的建设顺序

推荐：

### 第一阶段：

建立数据处理工具

例如：

* LSV自动处理
* Tafel计算
* EIS分析
* 自动绘图

### 第二阶段：

建立文献助手

例如：

* 自动整理论文
* 建立材料数据库

### 第三阶段：

建立表征辅助工具

例如：

* SEM分析
* XRD辅助判断

### 第四阶段：

整合Agent

让AI自动协调：

```
发现问题
↓
查文献
↓
分析数据
↓
生成报告
```

---

# 最终理念

不要追求：

“AI替我完成科研。”

而应该：

> **让AI消灭低价值重复劳动，让自己把时间投入到真正需要科研判断的地方。**

最优模式：

**固定任务 → 脚本自动化**
**变化任务 → Agent辅助**
**科学判断 → 人完成**
